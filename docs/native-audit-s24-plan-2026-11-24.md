# Isolated native S24 audit test

Mike authorized native S24 tests against local emulators: offline save/process restart, receipt retries and company switching; preserve Burger 1, signed records, other pending work and Tickets460; leave Fold alone; no deploy.

Use a separate local-only Android variant `com.syconik801.jsaapp.audit`, built in the registered JSA home with the existing approved signing key. The production package/version/entry point and data stay unchanged. No new repository, source checkout or cloud build. The test manifest has no production deep link or forms provider, uses a separate storage sandbox and disables backup/updates. Default release tooling is unchanged. The explicit audit runner adds its tracked Gradle configuration only to ignored generated native input, preserves the previous bytes privately and restores them afterward.

The same `createLegacyEvidenceClient` core is used by production wiring and the test variant. Production session/transport imports remain in the production wrapper; they are absent from the native test entry. The variant uses Hermes, actual native AsyncStorage and persisted Firebase Auth with synthetic custom-token identities, and actual Firebase Functions SDK calls to the local Functions emulator's real `jsaLegacyEvidence` export. No fake browser storage or HTTP RPC adapter is used for the receipt test.

Demo project only: demo-wb-audit-s24. USB loopback ports8789 fixture,9299 Auth,5001 Functions. Firestore/RTDB local ports8183/9190. Establish synthetic Auth online, remove emulator forwarding and disable S24 radios for the save, force-stop/relaunch the audit variant while still offline, then restore original radios/forwarding and retry. A post-commit response-loss injection must retain pending state until identical replay succeeds. Test A→B→A plus a switch while a request is in flight, foreign receipt denial, exactly one signed record and one receipt, and original signed JSON/time unchanged.

This tests native persistence/Auth/receipt transport and client core. It does not certify the full normal Tickets→JSA→Tickets UI, human preparedness/signature steps, prepared/standalone workflows or production rollout. No production app replacement, session switch, pending-queue action, inspection certification, printing or deployment is part of this test. Other-machine unpushed work cannot be discovered.
