# Continuous JSA background and header boundaries - 2026-10-19

Source-only fix; installed JSA65 unchanged. No APK built/installed, backend deployment, authentication/lifecycle or record changes.

Root cause: shared JsaAppBackground drew a faint blurred full-screen copy plus a second full-opacity photo positioned by width/aspect ratio and anchored above the footer. On tall phones the second photo began partway down the screen. Its hard top edge left a pale band across the upper viewport on every route; the band resembled an oversized header even under the Saved JSAs green header. Local header changes did not remove that shared compositing boundary.

Replaced the two layers with one aspect-preserving cover image filling the entire frame, plus the existing uniform wash. The same fix applies to water-hauling, LTL, aggregate and transportation packages and to all routes under the shared root. Photos crop naturally to each aspect ratio rather than stretching or starting below the header.

Audited header ownership across routes. Main/Job Details and Saved JSAs own their custom headers and retain top safe area. Native stack pages Steps (including loading/assessment states), PPE (including loading), Review/Signoff, Acknowledge, Submitted/Completed, Settings, legacy Open JSAs, PDF and legacy View JSA use left/right/bottom edges so they do not add a second status-bar inset below an already-safe native header. Review/PPE already had the correct normal-state edges and were preserved. New Open JSAs, JSA record, Add location and printer settings use the existing native header without extra top padding. Login/governed/status/return-only surfaces inherit the continuous shared background; no added second header. Stack headers explicitly remain opaque/nontransparent and stack content is clipped to the screen bounds. Saved JSAs FlatList has an explicit flex/clip viewport below its custom header.

Validation: full tsc passes. Actual shared React component rendered via React Native Web/Playwright with synthetic scroll cards across4 photo packages x3 viewports (411x960,768x1024,960x411): all12 images fill the viewport, all scroll viewports start at the fixed header bottom and end above the fixed footer. Inspected portrait/landscape screenshots; no offset photo edge or pale header extension. Browser fixture is visual/layout evidence for the shared component, not a claim that each authenticated native phone screen was exercised. Private screenshots/fixture remain under C:/dev/tmp/jsa-background-qa outside Git. Next JSA APK requires on-phone verification of Saved JSAs, first-read pages, signoff and record view.
